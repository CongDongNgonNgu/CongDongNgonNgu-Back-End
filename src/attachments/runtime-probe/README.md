# Explicit Render TEST processor smoke

This module is inert unless PHASE30_TEST_RUNTIME_PROBE_SHA explicitly equals the full reviewed Render dev commit. It is not an upload endpoint or format enablement gate. The launcher checks exact TEST service/branch/Linux x64, raw and effective TEST/disabled capabilities and absence of injected Node/native loader options before importing the runner. It starts once, after the existing app has listened. No retry or periodic probe exists.

The runner uses four immutable tiny synthetic inputs:32x24 JPEG/PNG/WebP and the independently hash-bound128x72/0.5s H264 SEI fixture. It uses the existing processors in the actual Nest process, with serial admission and unchanged native deadlines/threads/memory/temp constraints. No SQL fixtures, parent binding, R2 objects, credentials, user media or public media capability is involved. The normal app may retain its existing database connections.

Observations are bounded, credential-free loopback health requests, actual whole-app RSS, cgroup-v2 membership/current/finite limits/events and visible finite ancestors. Resource sampling continues until the processor settles; each stage rechecks admission before native work. Health request count is independently capped. The75percent observed cgroup margin is a conservative diagnostic stop, not a changed media policy. Missing/ambiguous measurements fail. Hidden ancestors remain UNVERIFIED; sampled maxima are not hard allocation ceilings or complete deployment headroom proof.

The overall150s cooperative timer cancels observations/work; existing processor shutdown is awaited with a5s bound. SIGTERM cancels active work and relays termination, with a5s exit fallback. OOM/SIGKILL cannot execute cleanup handlers. Exact-owned scratch is removed only when empty; unquiesced video scratch is preserved. No recursive wrapper cleanup overrides processor ownership. A tiny fixture success is reported only as PASS_TINY_FIXTURES_ONLY. It does not establish hardest accepted files, repeated peak/timeouts/cancellation, representative API interference, HTTP uploads, provider round trips, current-parent authorization or lifecycle cleanup.

After source review and all Backend dev/TEST CI gates, an operator may temporarily prefix the existing TEST start command with NODE_ENV=test and PHASE30_TEST_RUNTIME_PROBE_SHA=<exact-reviewed-dev-SHA>, retaining all four explicit ATTACHMENTS_* flags false. Never set this on Production/main. Restore the original default-off start command after the finite measurement, and independently verify exact deployment/logs and health. No default build/start command or repository deployment workflow is changed by this module.

RENDER_GIT_COMMIT/SERVICE_ID/BRANCH are Render deployment declarations, not independent compiled-artifact attestation. Correlate the exact Render deploy/source/build with the reviewed source and code-pinned processor verification. Official variable definitions: https://render.com/docs/environment-variables.
