# Internal finalization ledger

This slice performs SQL and pure byte checks only. It does not register routes, perform provider/native I/O, enable formats or claim runtime acceptance. Each method requires the caller's READ COMMITTED transaction; every error requires complete rollback.

1. claimProcessing freshly authorizes the immutable draft scope/generation, locks its attachment and exact settled source, then acquires the global singleton. It requires PENDING, a held pending slot, an unexpired unbound draft and no unresolved prior derivative attempt. It never steals an expired or unresolved producer lease. Commit the returned fence before reading/processing bytes.
2. The orchestrator reads/checks the exact source snapshot through the storage adapter, runs the reviewed native processor (or strict inert TXT validation), waits for actual child closure, and obtains moderation ALLOW. createProcessorProof is an internal trusted-server factory, never an HTTP DTO. Pure structural/hash checks cannot prove native execution against malicious server code; the trusted orchestrator is responsible for that execution and moderation gate.
3. prepareArtifacts freshly rechecks authorization/fence/source and issues immutable normalized/thumbnail manifests with consumed single-use PUT claims before I/O. Its sealed plan is a module-private WeakMap identity; client-shaped JSON and mutated public claim copies cannot create publication authority. processorProofArtifacts returns independent byte copies for the exact variant uploads.
4. After committing claims, PUT each exact immutable key once, record every completed result with AttachmentObjectLedger, and independently HEAD all selected source and derivative objects. publishReady rechecks current authorization/generation/version, all complete locator/hash/size/ETag snapshots, consumed settled claims, and format-specific sealed facts. It obtains objects/cleanup ownership before pending quota and the singleton lease last. READY selection, pending-slot release, source cleanup scheduling and singleton release commit atomically. Physical bytes/metadata reservations remain held.
5. Any deletion, revocation, expiry, missing object, uncertain write or changed lease fails closed. No raw source becomes a read fallback. A same-plan READY replay only confirms the exact already selected objects and performs no new upload or quota release.

IMAGE requires WebP normalized plus WebP thumbnail, VIDEO MP4 plus metadata-free JPEG thumbnail, and TEXT one inert application/octet-stream normalized object with no thumbnail. Selected derivative identities are immutable. TXT initial BOM normalization is allowed; the source receipt/hash remains the original replay identity.

The plan/proof is deliberately process-local, not a persisted client capability. If a process dies before publication, do not reconstruct a trusted native proof from database status or a client assertion. Preserve all ownership/debt and require proven producer quiescence plus reviewed rejection/cleanup/recovery before another attempt. No expiry, restart or missing process message establishes quiescence. Terminal lifecycle settlement is separate; this ledger has no automatic singleton reset.

A successful publication queues the selected original source for exact ORPHAN cleanup after READY. It does not delete or mark the source physically clean and does not release byte quota. The READY-source cleanup eligibility is handled by the separate lifecycle/cleanup port.

Guarded SQL tests use owned random schemas on the approved TEST database, synthetic metadata and settled-provider receipt fixtures. They establish database authorization/fencing/quota behavior, not actual durable storage, native processing, deployed HTTP behavior or security leak acceptance. Pure proof unit tests include controlled trusted-result fixtures; actual image/video pipeline tests establish native functional behavior separately. Exact Render/security/resource/provider acceptance remains required before enablement.
